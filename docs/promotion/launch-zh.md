# 做了一个东亚年号互换工具：贞观十九年对应日本什么年号？也能给 Agent 调用

短标题：**明正朔：把东亚年号放到同一条时间线上**

## 正文

读东亚史料时，一个很实际的问题是：同一年在不同地区、不同政权的文献里，究竟写作什么纪年？只把年号换成公元年还不够；跨地区对照时，还要从这个公元年继续找到另一套年号。遇到并立朝廷，也不能悄悄替使用者选掉其中一个结果。

我把这类查询做成了开源工具“明正朔”。它使用确定性数据和规则，在年号纪年与公元年份之间双向互换，也可以跨地区查询。比如输入“唐贞观十九年”，目标选择日本，结果是“唐贞观十九年 = 公元645年 = 日本大化元年”。输入“公元1338年”并查询日本，则会同时列出日本建武五年、日本北朝历应元年和日本南朝延元三年，保留并行结果及朝廷标识，而不是只返回一个看似简单的答案。

使用方式分三层。临时查阅可以直接打开网页；研究脚本或数据整理可以用 CLI 与 Python API，并通过 JSON 获得候选、地区、政权和历法元数据；支持 Agent Skills 的工具还可以把仓库作为 Skill 安装。本次已在干净的临时环境里完成非 editable Python 包安装，确认模块从虚拟环境的 `site-packages` 导入，并验证了模块入口和 console script。Skills CLI 也完成了公开仓库发现、项目级安装、文件完整性和安装目录内脚本运行，验证等级为 L2；真实 Agent 的自动识别与自动调用尚未作为 L3 验证，所以不作相应承诺。

明正朔当前只做年份级换算。输入里若带月日，例如“同治五年三月初八”，其中“三月初八”会原样保留，不能理解为已经完成阴阳历、旧历、儒略历或格里历之间的日期转换。数据覆盖仍在持续扩充，未收录不等于历史上不存在。默认的“正朔”线是项目公开说明的一套史学规则；需要中立比较时，可选择地区目标或查看全部并行候选。
